# 可复用的模型部署与 FPGA 验证技能包

本目录提供一个可加载的 [FPGA 模型部署 Skill](fpga-model-deployment/SKILL.md)、三条完整工作流、17 篇按问题查阅的操作方法、一个实验记录模板和三个校验脚本。提炼顺序依照跨项目出现的频率与决策价值：先处理数据、算子、数值、数据流、板级验证和交付身份；其余专题在触发具体问题时使用。所有方法以可替换的输入与可证伪的判断步骤编写，目标网络、器件、图像和性能数值不作为默认参数。

各方法在本工程中的观察与验证范围见 [证据索引](evidence_index.md) 和 [有效性矩阵](validation_matrix.md)。

## 推荐入口

1. [数据、模型与指标契约](workflows/data_model_contract.md)：审计数据、设计受控比较、建立量化与输出语义。
2. [算子到 FPGA 数据流](workflows/fpga_design_review.md)：比较落地路线、推导缓存和并行度、通过布线与板测筛选。
3. [黄金参考到板级交付](workflows/verification_release.md)：寻找首失配边界、定位时钟与存储问题、冻结构件版本。

先复制[实验记录模板](experiment_template.md)，填入输入哈希、假设、唯一改动、预期反证和回退版本。每轮只改变一个因素。

## 优先掌握的通用方法

| 使用情景 | 方法 | 核心决策 |
| --- | --- | --- |
| 更换数据、分辨率或指标 | [数据集契约](dataset_contract.md) | 先确认标签、分组和比较口径，再解释模型差异 |
| 新网络移植到已有加速器 | [算子映射](operator_mapping.md) | 比较专用 PL、PS 分段和结构替换的整机代价 |
| 浮点正确而整数结果异常 | [量化契约](quantization_contract.md)、[输出语义](tensor_contract.md) | 找首个语义相同的张量边界，不把编码差异误判为算术错误 |
| 资源和延迟需要共同优化 | [PL 数据流](pl_dataflow.md)、[HLS 优化](optimization.md) | 让访存复用、II、资源、布线和板测共同决定候选 |
| C 仿真通过而板端异常 | [板级失配](board_mismatch.md) | 用固定输入和缓冲区快照收窄到首个失配边界 |
| 多个构件需要复现和交付 | [版本身份](release_identity.md) | 固定模型、IP、位流、软件和报告的依赖关系 |

这些方法从稠密数据通路探索、YOLO26n 结构定型、INT8 实现、板级收敛和交付验证各阶段反复出现的决策问题中提炼，适用对象是需要把模型部署到资源受限 FPGA 的开发者。下面的其他专题用于深入处理训练增强、缓存复用、AXI、显示状态和领域预处理；选择由当前问题决定。

## 问题索引

| 方法 | 什么时候用 | 主要输出 | 不适用或易误用的情况 |
| --- | --- | --- | --- |
| [数据集契约](dataset_contract.md) | 换数据或输入尺寸 | 标签/分组审计和同条件比较 | 跨数据集精度差不能解释尺寸收益 |
| [领域训练](domain_training.md) | 增强可能改变任务语义 | 增强决策与指标选择 | 不同成像模态不能照搬增强 |
| [算子映射](operator_mapping.md) | 内核缺少某算子 | PL/PS/结构替换决策表 | FLOPs 不能代表整机成本 |
| [结构替换](model_surgery.md) | 为部署改网络模块 | 单层、任务、硬件三层验证 | 浮点等价不证明定点或板级等价 |
| [量化契约](quantization_contract.md) | 浮点正确而 INT8 异常 | 首失配层与标定复测 | 不同量化格式不能共用零点公式 |
| [激活快照](activation_snapshot.md) | 工作区地址会复用 | 逐层可比激活 | 结束后不能回读已覆盖层 |
| [输出语义](tensor_contract.md) | 参考与实现看似误差大 | 张量契约表 | 同形状不代表同语义 |
| [板级失配](board_mismatch.md) | C 仿真通过、板端失败 | 首差边界与反证实验 | 单样例恢复不证明全量正确 |
| [HLS 活性](hls_liveness.md) | 启动后无完成状态 | 控制/总线/循环分叉 | 超时不必然是计数器问题 |
| [时钟契约](clock_contract.md) | 排程与实际频率需核对 | 时钟表与重复输出 | 正 WNS 不证明数值正确 |
| [存储边界](memory_boundary.md) | DDR/AXI 访问异常 | 地址、对齐与 cache 检查 | 字节访问不应全局替换宽访问 |
| [PS—PL 协议](ps_pl_protocol.md) | 共享内存调用或结果展示 | 所有权与状态转移图 | cache API 和寄存器因平台而异 |
| [PL 数据流](pl_dataflow.md) | 资源或路由成为瓶颈 | tile/bank 与资源时序对照 | 并行度不能跨网络照搬 |
| [HLS 优化](optimization.md) | 候选声称提速 | 假设—证据—决定表 | II 改善不等于整机提速 |
| [整机剖析](end_to_end_profile.md) | 用户等待远大于内核时间 | 分段 wall 与未计时差额 | 单次内核时间不能给整机 FPS |
| [预处理消融](filter_ablation.md) | 个例增强似乎有益 | 逐图配对 TP/FP/FN | 视觉清晰或置信度不能代替检出 |
| [版本身份](release_identity.md) | 模型/IP/程序可能混配 | 构件依赖图与哈希清单 | 哈希不证明授权或功能正确 |

## 可直接运行的工具

- audit_dataset.py：检查 YOLO 图像/标签配对、标签格式与可选分组交叉。输入为数据根目录和可选划分 CSV；不能判定标注是否真实。
- compare_buffers.py：比较同一语义边界的两份二进制缓冲区，给出长度、SHA-256 和首差字节；使用者必须提供 dtype、shape 和步长。
- audit_vivado.py：从实现后的 Vivado 报告读取资源与 WNS/WHS；必须核对报告属于当前 bitstream，且关键路径受约束。

运行参数见各脚本的 --help。脚本返回非零状态表示检查失败；不要把单个脚本通过解释成整套工程通过。

## 使用与验证界限

将方法迁移到其他模型或器件时，先替换数据契约、算子图、总线宽度和验收阈值，再按[实验记录模板](experiment_template.md)记录输入、修改前后证据和反例。校验脚本已用于本工程数据、实现报告及合成缓冲区；新平台仍需重新验证。
