# 从黄金参考到板级交付的分级验证

**适用范围**：软件参考、HLS C 仿真、实现报告和板端结果需要形成同一版本的证据链。可用于检测器，也可用于其他有固定输入/输出缓冲区的加速器。

## 使用前填入

固定输入及哈希；参考张量的语义、形状和布局；模型/参数/层表哈希；HLS 源码、IP、bitstream、PS 程序和 BOOT 的生成关系；目标板卡与时钟。

## 工作流

1. 先核对同一语义边界：输入、逐层激活、原始输出与后处理结果。复用工作区的激活应在层完成时快照，不能结束后回读旧地址。
2. C 仿真通过后，在板端按输入→工作区→预测→软件后处理逐边界找首失配点。用 `compare_buffers.py` 比完整哈希和首差偏移；若边界数据不可导出，先补最小插桩。
3. 首失配落在 PL 时，分别检查实际 HLS/BD 时钟、复位、AXI 地址/对齐、缓存所有权和 RTL 循环退出条件。一次只改变一个假设，保存相反结果的解释。
4. 修复后重做 C 仿真、综合布线和同输入板测。将 WNS/WHS 与资源由 `audit_vivado.py` 提取，附原始报告；板端保存串口、图像 ID、输出及重复次数。
5. 按构件依赖图生成哈希清单。重新打包或复制到 SD 后复核内容，禁止把不同版本的参数、位流和程序混用。

## 验收与边界

同一输入与构件版本下，参考/HLS/板端的约定输出一致，目标时钟时序通过，板端功能和耗时留有原始记录，才称交付。正 WNS 不单独证明数值正确；单样例修复不证明全验证集；一次耗时不能提供波动或稳定 FPS。

分项检查见[板级失配](../board_mismatch.md)、[时钟](../clock_contract.md)、[存储](../memory_boundary.md)、[HLS 活性](../hls_liveness.md)与[版本身份](../release_identity.md)。根因优先级应由当前边界证据决定，不按案例发生次数排序。
