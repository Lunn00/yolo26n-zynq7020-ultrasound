# 软硬件系统的端到端耗时剖析

## 适用范围与输入

适用于内核时间看似较短，但用户操作或批处理明显更慢的系统。准备完整调用路径、单调计时器、输入 ID、运行模式和编译设置。

## 插桩流程

1. 在用户动作开始和可见结果完成处定义 wall；为读取、解码、预处理、缓存维护、加速器等待、后处理、显示分别取时间戳。
2. 把日志打印放在计时结束后，输出每段耗时与 wall 减去已计时段之和。差额过大时先补计时点。
3. 把首次运行与连续运行、缓存冷态与热态分开；同一输入和模式至少重复记录，不混合平均。
4. 根据占比选择单一优化对象。修改软件优化级别、文件读取粒度或像素算法时，先比功能与输出，再比 wall。
5. 同时报告“内核等待”“完整推理调用”“用户完整等待”三个边界，不用某一个的倒数冒充整机吞吐。

## 输出与边界

交付分段表、未覆盖时间、改动前后完整 wall 与原始日志。时钟采样、串口和 UI 刷新可能本身改变耗时，应在同一测试设置下比较；单次结果不能估计 P95 或稳定 FPS。
