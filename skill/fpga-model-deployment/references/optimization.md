# HLS 优化的可证伪实验方法

## 适用范围与输入

适用于候选修改声称能提速、减资源或改善时序。准备固定输入、基线构件身份、候选源码、可比较的输出边界、HLS schedule、实现报告和同口径板端计时。

## 实验设计

1. 先把瓶颈写成可证伪假设，例如“某类访存事务限制吞吐”或“某个写回循环的 II 主导总时长”。写出若假设为真与假各会观察到什么。
2. 能独立调整的机制分别试验；必须联动的源码、参数与接口作为一个候选记录。保持与假设无关的模型、输入、软件、时钟和计时边界一致，并保存回退版本。
3. 比较与修改有关的完整输出；若工作区复用或难以导出，在最早可观察边界取快照。数值不一致的候选先定位错误，不进入速度比较。
4. 依次记录关键循环 II/周期、LUT/BRAM/DSP、WNS/WHS 和同图板端耗时。将资源与时序裕量的变化和实际收益并列，判断候选是否值得保留。
5. 若局部指标改善而整机时间不变，缩小原假设并检查控制开销、其他循环和软件边界，再决定是否继续同类优化。

## 判定与输出

输出“假设—候选改动—预期—实测—决定”表。接受候选须同时通过数值、可实现性和板上同口径验证；缺任一证据，状态为待验证。重复试验才能估计波动，单次反馈只作为单次观察。

## 失效边界

HLS II 降低不等于整网按比例提速；DDR 事务数量不等于实际访存等待；布线 WNS 接近零时任何变更都需重新实现。
